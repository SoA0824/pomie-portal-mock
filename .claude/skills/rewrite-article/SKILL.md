# 記事のリライト

公開中・下書きの記事を、指示に沿ってリライトする。**記事は直接書き換えない。** リライト案を「提案」として保存し、
管理者が管理画面（記事の編集画面の「リライト」欄）で差分を確認して「承認して反映」したときだけ記事に反映される。

書き方・表現のルールは `docs/ARTICLE-GUIDELINES.md`。最初に読む。

## 使い方

- `/rewrite-article` … 管理画面で出されたリライトの依頼を順に処理する
- `/rewrite-article omotesando-head-spa 専門店との違いの章を厚くして` … チャットから依頼して、そのまま処理する
- `/rewrite-article omotesando-head-spa を分析して` … 分析だけ（保存しない）
- Search Console の CSV（検索パフォーマンス → クエリ → エクスポート）を渡されたら `--gsc` で使う

## 手順

1. 依頼を確認する
   ```bash
   node scripts/articles/rewrite.mjs list
   ```
   チャットで依頼されたときは、先に登録する:
   ```bash
   node scripts/articles/rewrite.mjs request --article <slug> --instruction "<指示>" [--remove st-a] [--add st-b]
   ```
   - 失敗したら: テーブルが無い → `supabase/migration-012-article-revisions.sql` の実行を依頼

2. 材料を取る（依頼ごと）
   ```bash
   node scripts/articles/rewrite.mjs context <依頼ID> [--gsc <CSV>]
   ```
   - JSON（材料）と、今の記事を書き出した編集用ファイル `content/rewrites/<slug>.md` ができる
   - 紹介する美容師は、差し替え後の値が初期値として入っている
   - 表示される「気になる点」を確認する（非公開になった美容師、料金・施術時間のずれ、検品の指摘、食い合う記事、追加できる美容師、Search Console の「あと一歩」のクエリ など）

3. 分析する（ここは自分で考える）
   - 依頼の指示が最優先。指示が曖昧なら、気になる点から改善の方針を決める
   - Search Console のデータがあれば: 掲載順位 8〜20 位のクエリ → その語の見出し・説明を補う／クリック率の低いクエリ → タイトル・概要を見直す
   - データが無い場合は、検品の指摘・情報の鮮度・美容師情報のずれを中心に直す
   - 必要なら、ラッコキーワードのコネクタで `suggest-keywords` / `question-search` を使ってよい（**1 依頼 10 クレジットまで**）

4. リライトする（`content/rewrites/<slug>.md` を編集）
   - **原型を保つ**: 見出しの構成・主張・良い部分は残す。指示がない限り、全面的な書き直しや構成の大きな変更はしない
   - **URL（slug）は変えない**（ファイルにも書かない）。`base_updated_at` の行は消さない
   - **美容師の差し替え**: 外す美容師の名前・リンク・メニューの記述を消し、加える美容師を、その人の公開情報（材料の JSON の `stylists.add`）だけで紹介する。`related_stylist_ids` も合わせる。本文の他の箇所に残った名前も探して直す
   - 料金・施術時間・メニューは、材料の JSON にある今の値に合わせる
   - 美容師の発言・施術例・お客様の声を創作しない。断定できないことは `[要確認: …]`
   - タイトルを変える場合も、キーワードを前半に、32 文字以内

5. 検品して保存する
   ```bash
   node scripts/articles/rewrite.mjs save <依頼ID> --file content/rewrites/<slug>.md \
     --analysis "<分析の要約（3〜6 行）>" --summary "<変更点の箇条書き>"
   ```
   - エラーがあれば直してからもう一度
   - `--analysis` には「何が問題で、なぜその直し方にしたか」、`--summary` には「どこをどう変えたか」を書く（管理者が承認の判断に使う）
   - どうしてもリライトできない場合は `node scripts/articles/rewrite.mjs fail <依頼ID> --reason "<理由>"`

6. 報告する
   - 分析の要点、変更点、`[要確認]` があればその一覧
   - 「記事の編集画面の『リライト』欄で差分を確認し、『承認して反映』してください」と案内する（URL は save の出力に出る）

## してはいけないこと

- 記事を直接更新する（`articles` を書き換えない。必ず提案として保存する）
- slug を変える
- 指示にない全面書き直し
- 美容師の公開情報にない内容（経歴・発言・施術例）を書く
- ラッコキーワードのクレジットを 1 依頼 10 以上使う
