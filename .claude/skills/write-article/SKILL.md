# 記事の自動執筆

POMiE ポータル（https://portal.pomie.jp）の記事を、キーワード選定からリサーチ、執筆、検品、下書き保存まで行う。
**公開はしない。** 保存される記事はすべて「下書き」で、運営が管理画面で確認してから公開する。

編集方針・表現のルールは `docs/ARTICLE-GUIDELINES.md` にある。**最初に必ず読む。**

## 使い方

- `/write-article 表参道 髪質改善` … このキーワードで 1 本書く
- `/write-article 恵比寿で白髪ぼかしをしたい 40 代向けの記事` … テーマから書く（キーワードはこちらで決めて提案する）
- `/write-article --approved` … 管理画面で承認済みのキーワード候補から 1 本書く（承認フローの記事化）
- `/write-article --approved 3` … 承認済みの候補から 3 本書く
- `/write-article` … キーワードの候補を出して、どれを書くか聞く（候補を DB に登録するなら `/propose-keywords`）
- 「候補だけ出して」「3 本まとめて書いて」など、言われた範囲に合わせる

## 準備

1. `docs/ARTICLE-GUIDELINES.md` を読む
2. 材料を取る:
   ```bash
   node scripts/articles/context.mjs --keyword "<キーワード>" --out /tmp/pomie-article-context.json
   ```
   出力の JSON を読み、次を把握する:
   - `stylists` … 掲載中の美容師。**記事に書いてよい美容師の情報はここにあるものだけ**
   - `articles` … 既存記事。`keywordCheck.verdict` で重複を確認する
   - `taxonomy` … メニュー・強み・エリアの一覧（キーワードの種）
   - `links` … サイト内リンクの形式
   - 失敗する場合: `.env.production.local` が無い → ユーザーに設定を依頼する（本番サイトと同じ DB に保存するため）。記事テーブルが無い → `supabase/migration-008-articles.sql` の実行を依頼する

## 承認済みの候補から書く場合（--approved）

管理画面 `/admin/keywords` で承認された候補を記事にする。キーワード選定は済んでいるので、手順 1 の代わりに次を行う。

1. 候補を取る:
   ```bash
   node scripts/articles/candidates.mjs list --status approved
   node scripts/articles/candidates.mjs show <候補ID>
   ```
   スコアが高い順に書く。`note`（運営のメモ）があれば最優先で従う
2. 候補の `suggestedTitle` / `angle` / `category` / `targetStylistIds` を企画の出発点にする（より良くできれば変えてよい）
3. `faqQuestions` が空なら、コネクタの `question-search`（中心語、`limit` 20）と `suggest-keywords`（キーワード、`limit` 30）で材料を取る（10 クレジット）
4. 以降は手順 2〜5 と同じ
5. 保存は候補と紐づける:
   ```bash
   node scripts/articles/save.mjs content/drafts/<slug>.md --candidate <候補ID>
   ```
   候補が「記事化済み」になり、記事一覧に下書きとして並ぶ
6. 報告には「`/admin/articles` でプレビューを確認し、監修者を付けて『承認して公開』してください」を含める

## 手順 1. キーワード選定

### キーワードが指定されたとき

1. ラッコキーワード MCP の `suggest-keywords`（`keyword` にそのキーワード、`limit` 40 程度）で、検索数・難易度・複合語を確認する
2. `question-search`（`limit` 30 程度）で、実際に検索されている質問を集める（よくある質問の材料）
3. `keywordCheck` で既存記事と重なっていたら、切り口を変えるか、ユーザーに相談する
4. 掲載中の美容師に、そのメニュー・エリアに対応できる人がいるか確認する。いなければ「送客先が無い」と伝え、近いキーワードを提案する

### 指定が無いとき（候補出し）

1. `taxonomy` と `stylists` から、**実在の美容師が対応できる**メニュー × エリアの組み合わせを 3〜5 個選ぶ
2. それぞれ `suggest-keywords` で検索数と複合語を取る（1 回 5 クレジット。合計 15〜25 クレジットまで）
3. 候補を 5〜8 個、次の表で出す:
   - キーワード / 月間検索数 / 難易度 / 検索意図（予約に近いか） / 送客できる美容師 / 既存記事との重なり
4. **おすすめを 1〜2 個に絞って理由を添え**、どれを書くかユーザーに聞く

クレジットの目安: 1 記事あたり 15 クレジット以内。`search-volume-history` は使わない（1 回 50 クレジット以上）。
ラッコが使えない（ツールが無い・エラー）ときは、WebSearch で「<キーワード>」「<キーワード> とは」「<キーワード> おすすめ」の結果と関連質問から代替する。

## 手順 2. リサーチ

1. WebSearch で「<キーワード>」を検索し、上位 5〜8 件のタイトルと内容の傾向を見る
2. WebFetch で上位 3 件程度を読み、次をメモする（**文章は写さない。構成と論点だけ**）:
   - どんな見出し（論点）が共通して扱われているか
   - 読者が本当に知りたいこと（料金、頻度、失敗例、選び方 …）
   - 上位記事に無い、このサイトなら書ける切り口（美容師の得意・エリア・料金目安との結びつけ）
3. 事実として書きたいことで、根拠が要るもの（相場、持続期間、頻度など）は、信頼できる出典が見つかったときだけ書く。見つからなければ一般的な目安として弱く書くか、`[要確認: …]` を付ける

## 手順 3. 構成案

書き始める前に、次を決めてユーザーに**短く**見せる（承認を待たずに進めてよいが、方向性が分かるように）:

- タイトル案（32 文字以内、キーワードを前半に）
- `## ` 見出しの一覧（3〜6 個）＋「よくある質問」の質問 2〜4 個
- 紹介する美容師（1〜3 名）とその理由
- 入れるサイト内リンク

複数本を頼まれたときは、1 本ずつ「構成 → 執筆 → 保存」を回す。

## 手順 4. 執筆

`content/drafts/<slug>.md` に、次の形式で書く。

```markdown
---
title: 表参道で髪質改善。くせ・広がりに合うメニューと美容師の選び方
slug: omotesando-kamishitsu-kaizen
category: ケア
summary: 表参道で髪質改善を考えている方へ。縮毛矯正・酸熱トリートメントなどメニューの違いと料金の目安、失敗しない美容師の選び方を、ポミエの美容師情報とあわせて紹介します。
target_keyword: 表参道 髪質改善
related_stylist_ids: [st-47e9gf]
cover_image: /images/stores/s1.jpg
---

（書き出し 2〜4 文。キーワードを含める）

## 見出し 1
...
```

- `category` は カット / カラー / メンズ / ケア / エリア のいずれか
- エリア（`areas`）は省略可。キーワード・タイトルの地名、無ければ紹介する美容師の店舗から自動で付く。`omotesando` / `ebisu` は slug に使えない
- `slug` は半角英小文字・数字・ハイフン。内容が分かる英単語（日本語のローマ字でも可）
- `cover_image` は任意。エリアの記事なら店舗写真（`/images/stores/s1.jpg` = 表参道、`s2.jpg` = 恵比寿）を使ってよい
- 本文はガイドラインの「記事の型」に従う。**送客セクションとよくある質問は必須**
- 美容師について書くのは `context.mjs` に出ている公開情報だけ。発言・施術例・お客様の声を作らない
- 表（`|`）は使わない。画像は入れない

## 手順 5. 検品

```bash
node scripts/articles/check.mjs content/drafts/<slug>.md
```

- `✗`（エラー）が無くなるまで直す。表現のエラーは、指示された言い換えに沿って書き直す
- `!`（注意）は内容を見て判断する。直せるものは直す
- `[要確認]` を付けた箇所は、報告で必ず一覧にする

## 手順 6. 保存

```bash
node scripts/articles/save.mjs content/drafts/<slug>.md
```

- 下書きとして保存され、プレビューと編集の URL が表示される
- 同じ slug の下書きが既にあるときは、意図して上書きする場合のみ `--force` を付ける
- 公開中の記事は上書きできない（管理画面で編集する）

## 手順 7. 報告

次をまとめて伝える:

1. キーワードと選んだ理由（検索数・難易度・既存記事との関係）
2. タイトル・概要・見出し一覧
3. 紹介した美容師とリンク
4. **`[要確認]` の一覧**（運営が確認すること）
5. プレビュー URL と編集 URL
6. 公開前のチェックリスト（`docs/ARTICLE-GUIDELINES.md` 8 章）への誘導

公開は行わない。「公開しますか？」とも聞かない（管理画面で運営が行う）。

## してはいけないこと

- 記事を公開状態で保存する（`save.mjs` は常に下書きにする。管理画面の API を直接叩かない）
- 他サイトの文章を写す（構成と論点の参考にとどめる）
- 美容師の発言・施術例・口コミを創作する
- `context.mjs` に無い美容師・店舗・料金を書く
- ラッコキーワードのクレジットを 1 記事 15 を超えて使う（候補出しは 25 まで）
- `search-volume-history` を呼ぶ（ユーザーが明示的に頼んだときだけ）
